## II. What Not to Do

| Topic | Rules |
|-------|-------|
| Do not add to the short table | Activity logs with no finding; FOFA result counts; what a site was tested for today; login-wall-only work; re-confirming a similar site; a path used once; target hosts without a delivered report; literal full tokens/keys. Do not add Medium issues even when exploited. A severity label that does not meet the report format’s “Severity” criteria (compare the body; if none match, it is not High) does not qualify; the title “High” is not enough. Do not add generic probes without new recognition (change ID, empty password, `omit`, list auto-increment, sending `'` to every path). The gate and then the three questions must pass before any short-table entry. Not adding to the short table does not mean skipping a matrix type. Still test login/reset/rebinding/ticket replacement under `dig-scope` §4.2.2. |
| Prohibited | Pretend a summary is hunting progress; spend more than 30 seconds polishing a row. Turn the short table into a diary, weekly report, or host dossier. Add low-value material; add every High issue automatically; assume “not in the knowledge base” means “add it”; create a new row when a similar row exists; fail to update an existing row despite a new differential; change “recognize” into a product/path list while updating; weaken success to signature-passed/parameter-missing/HTTP 200; force in a too-narrow item that cannot be recognized on a similar product; write a useless report just to teach the same pattern (testing it is fine). Apply a row mechanically; stop because the table has no entry; treat the table as the only checklist for this site. Delete a technique because it failed on one site or record “did not break through” as a false lead. Prune the old knowledge base to prevent bloat; delete entries that can still produce High findings; split many short tables by date; read the entire knowledge base at every site. Use “save tokens/read only this section” as an excuse not to open a needed module or test a type. Make a finding you discovered yourself wait for the user to say “add it.” Leave a user-provided, understood, worthwhile update waiting for “permission.” Interrupt the one-seed loop to consult the table. Use “iteration” as an excuse to investigate/search/test fewer things. Start a task without `线程必读.md`; end a subthread handoff with only “write report”; let a subthread edit the short table; have the main agent fail to collect proposals. Treat iteration as a reason to block site switching or wait for a table merge before `dig-scope` §4.3. Shorten the existing knowledge-base text just to make it shorter. Interpret “no execution key extracted” as “never test execution on this site”; treat execution examples as a whitelist; ignore execution surfaces omitted from the checklist; put RCE ahead of ID changes/password changes as the main focus; recognize an execution pattern and open a new-seed FOFA search; interpret opening a module as permission to test only its one table probe or switch to jailbreak testing; mark all of RCE N/A because no word was found on the homepage (the checklist/traffic/responses have not yet been examined). |
| Reporting | Governed only by `vuln-report-format.md`. This table does not govern whether CORS/code sending/uploads belong in a report; it only says Medium issues do not enter the short table. The short table and modules do not assign severity and must not create a separate severity recommendation table. Put long details in the corresponding existing module; leave only a pointer in the short table. |
